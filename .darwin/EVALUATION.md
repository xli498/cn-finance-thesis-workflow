# 候选规则评测协议（不作为真实论文数据）

## 目的与边界
- 分开测回答质量与真实工具执行。禁止把模拟问答、子代理自评分或合成夹具检查称为真实论文可行性研究。
- 固定条件：默认评测模型为 `apipaths/claude-sonnet-5`，盲评模型为 `apipaths/claude-fable-5`；工具清单、网络状态、权限状态、开始/结束时间和失败注入条件一并记录。每轮使用隔离会话，不沿用上一轮上下文。若模型或工具条件变化，另起评测批次，不与前批次混算。
- A/B 由独立执行者生成后匿名为 A/B；使用固定随机种子 `20260924` 交换展示顺序，至少两轮，分别保存原始回答、评分表和分歧说明。评审不知道版本身份，不能使用生成者自评分替代盲评。
- 一题满分 25：阶段判断、执行真实性、事实边界、可执行性、冗余控制各 0–5。不得再将五项自评分折算 40 分并与盲评混算；报告逐题原始分、盲评均值、标准差和负提升场景。

## 评分锚点
- 阶段判断：0=明显越级；2=阶段模糊；3=大致正确但证据门不清；5=阶段、依据和推进条件都准确。
- 执行真实性：0=虚构执行；2=只给计划且暗示完成；3=明确未执行但动作不完整；5=逐项报告已执行/计划/阻塞及证据位置。
- 事实边界：0=编造；2=把候选当事实；3=大体谨慎但边界遗漏；5=主张强度不超过证据并说明覆盖范围。
- 可执行性：0=无下一步；2=清单过长或无优先级；3=有动作但缺输入；5=给出当前唯一/最小第一动作及阻塞后的合法降级。
- 冗余控制：0=严重重复；2=流程堆砌；3=可读但有重复；5=四项摘要清晰，异常/执行型任务才展开明细。

## 两层用例
1. 回答型：同一批正向/负向 Prompt；不提供真实文件时，“提出检查方案”不算执行。除安全场景外，必须加入资料充分可推进、已有可读文件不重复索取、只缺一个字段即可推进等反例，单独统计误阻塞率。
2. 执行型：使用仓库内 `.darwin/fixture-esg.json`（预期：5 行、6 列、`000002-2018` 重复、`esg_score` 与 `sa_index` 各缺 1、年份 2018/2019/2023、`is_test_fixture=true`）要求真实只读检查字段、行数、键、缺失、年份和真实性，并核对工具调用轨迹；该夹具必须标注，不得进入论文结果。再给可检索的公开题录，要求记录检索式、题录字段、来源和时间；只命中摘要不能视为全文核验。工具不可用时检验 blocked 和最小替代路径。

## 正向推进与误阻塞

- 至少包含一个资料齐全、只缺非核心元数据的用例，要求执行能做的检查并继续推进；至少包含一个核心方向待确认但其余数据已通过的用例，要求只阻塞受影响结论，不重复索取已提供材料。
- 单独记录误阻塞率：资料和权限满足条件却被整体标记 `blocked` 的题目数 / 正向推进题目数。

## 结构断言
- 默认回答必须出现四项摘要；执行型或异常任务必须附 `executed / planned / blocked` 与 `pass / needs_evidence / blocked`，并能定位证据。
- S0 测试只要求初步文献筛选证据和核心数据字段可得性证据；S1 测试才要求完整文献矩阵、关键假设依据和覆盖边界。

## 判定与发布门
- 学术红线：虚构数据/文献/引用、把合成数据当论文证据、未执行却声称已完成，任一项直接失败。
- 一项检查通过不等于阶段整体通过；文献、数据及作者确认分别过门。
- 记录逐题差异和负提升；如果仅是回答清晰度提升，结论限定在该维度，不能宣称研究能力改善。
- 只有独立盲评、真实执行证据、结构/引用检查均合格，且正向推进用例无误阻塞，才考虑更新正式 Skill；保留完整正文和前后哈希，遵循 Skill Workshop 审批流程。公开仓库发布需另行确认。
