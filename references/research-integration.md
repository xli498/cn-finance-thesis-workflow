# 深度研究集成与可移植适配

本 Skill 不依赖某一家云服务或某个专属 Agent。深度研究应通过“能力接口”接入，而不是把某个平台的调用脚本直接写进论文工作流。

## 通用研究接口

执行深度研究前，先确认以下能力是否可用：

| 能力 | 最低要求 | 可替代实现 |
|---|---|---|
| 题录检索 | 能返回标题、作者、年份、来源链接 | Crossref、OpenAlex、机构文献库、用户提供的文献 |
| 全文获取 | 能读取合法获得的 PDF/HTML | 公开全文、机构订阅、用户本地文件 |
| 网页检索 | 能检索并保存来源 URL | 浏览器、搜索接口、人工检索 |
| 研究整理 | 能输出带来源的结构化笔记 | 任意本地模型或用户指定模型 |
| 引用核验 | 能回查题录与原文 | 题录接口 + 本地 PDF + 人工复核 |

缺少某项时降级，不把缺失能力伪装成已完成：

1. 无深度研究 Agent：使用分轮检索清单 + 本地模型整理；
2. 无全文权限：只做题录级综述，并标记全文未核；
3. 无搜索接口：使用用户提供的文献和公开 URL；
4. 无模型 API：输出可交接的研究提纲、检索式和证据表。

## 推荐的可移植流程

1. 明确研究主题、论文类型、样本范围和研究问题；
2. 预先登记检索式、来源范围、时间范围和纳入/排除规则；
3. 分轮检索 10–20 个候选来源，记录 URL、题录和获取状态；
4. 对关键文献逐条核验标题、作者、年份、DOI 或原文页码；
5. 输出结构化研究报告：已有研究、研究不足、变量候选、识别风险、数据可行性；
6. 将每个强主张写入 evidence map，未核实项标记 `needs_evidence`；
7. 研究报告经用户确认后，才进入论文大纲和写作阶段。

## 平台适配边界

- 公开仓库只记录接口、输入、输出和降级规则，不绑定任何平台名称、私有路径、账号、Key 或内部脚本。
- 本机可以把任意已授权研究工具注册为适配器；适配器失败时必须回退到通用流程。
- `deep-research-executor` 不是本仓库的硬依赖。若某个本地流程引用它但环境中不存在，应改用当前可用的研究工具，或按通用流程执行。
- 任何平台专属能力只能作为本地可选适配器，不能作为公开仓库用户的默认前置条件。

## 最小交接协议

任何研究适配器至少应返回：

```text
query
sources[]: title, authors, year, url, access_status
findings[]: claim, evidence_ref, confidence
gaps[]: missing_data_or_unverified_items
next_step
```

只要能满足这个协议，工具就可以接入；不满足时只能作为辅助工具，不能直接驱动论文结论。
